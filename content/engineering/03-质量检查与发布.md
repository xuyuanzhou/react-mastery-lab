# 工程实践 03：质量检查、构建与发布

一个能在开发机运行的页面，不等于可以稳定发布的应用。这个项目的质量门槛是：类型检查、ESLint、行为与内容检查、生产构建，然后才部署。

## 本地与 CI 用同一命令

```bash
npm ci
npm run check
npm run preview
```

`npm ci` 根据锁文件安装确定的依赖版本。`npm run check` 串起静态检查、测试和构建。GitHub Pages 的 [部署工作流](project:.github/workflows/deploy-pages.yml#L1) 也运行同一套检查，成功后只发布 `dist/`。

`index.html` 是 Vite 的开发入口，里面的 `/src/main.tsx` 不是应直接发布的浏览器文件。生产构建会把它转换成 `assets/*.js`，并按 [Vite 配置](project:vite.config.ts#L1) 的 `base: "./"` 生成适合仓库子路径的相对地址。曾经线上 404 的根因就是把开发入口当成了发布产物，而构建流程又被失败的测试挡住。

## 测试什么

- 教学模型的关键不变量，例如 UpdateQueue 的跨 Lane 重放。
- 教材内链与源码锚点是否能解析。
- React 官方源码版本、许可证与文件索引是否一致。
- 课程索引是否完整，正文是否从首页脚本分离。
- 本项目源码快照只包含明确允许公开的文件。

不要把每个实现细节都写成脆弱的断言。例如新增课程后，「恰好 110 篇」会错误地失败；「不少于既定基线」才表达真正的防回归意图。

## 发布前检查

检查仓库是否有未提交的个人文件、密钥或环境变量；构建器只发布白名单中的本项目源码文件。审查 `dist/` 的内容和大小，确认页面资源来自仓库子路径。发布后检查线上 HTML、主脚本、教材正文和源码索引都返回成功，再在浏览器实际打开一个章节。
