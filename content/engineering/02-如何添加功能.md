# 工程实践 02：用一个完整流程添加功能

以「新增一篇工程课程」为例，沿着数据流完成，不先修改页面组件。

## 1. 确定需求与边界

需求：新章节出现在「工程实践」分组，能阅读、搜索、收藏，且能打开本项目源码。数据源是 `content/engineering/*.md`；学习进度仍在浏览器本地，不引入服务端。

## 2. 添加内容与可验证链接

新增 Markdown 后运行 `npm run index`。构建器 [scripts/index.mjs](project:scripts/index.mjs#L1) 生成课程清单、全文搜索索引和本站可读取的正文。正文里可写：

```markdown
[阅读进度 Hook](project:src/features/progress/useProgress.ts#useProgress)
[React 官方 Hook 实现](source:packages/react-reconciler/src/ReactFiberHooks.js#renderWithHooks)
```

两种协议显式区分项目与框架源码。不要把任意线上 URL 当作可验证的函数锚点。

## 3. 把数据、状态和视图分开

[useProgress](project:src/features/progress/useProgress.ts#useProgress) 保存「已读、书签、最近访问、主题」，同时处理 `localStorage` 不可用的情况。UI 读取这个 Hook 的状态，不在多个组件里直接拼接存储键。

未来做用户登录时，可以在功能边界后面替换存储适配器，再考虑服务器同步和冲突策略；不需要先把所有本地状态搬到全局状态库。对于服务器数据，应单独定义请求层、加载/失败/重试状态和缓存策略。

## 4. 验证关键行为

运行 `npm run check`，它会检查规则、测试与生产构建。测试优先验证可观察结果：章节是否进入索引、链接能否找到文件、固定源码版本是否正确。不要只测试「某字符串出现在某个组件文件里」。

提交时说明：用户能看到什么变化、为什么这样设计、跑过哪些检查。不要提交 `dist/`、依赖目录或生成索引。
