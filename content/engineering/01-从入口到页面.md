# 工程实践 01：从入口到页面，认识一个标准 React 工程

这组课程研究的对象是 **React Mastery Lab 自身**。右侧源码面板切换到「本项目源码」，就能对照本章阅读真实代码。它与「React 官方源码」是两个不同范围：前者教你组织应用，后者教你理解框架内部。

## 先分清四层

```text
content/ Markdown 教材（源数据）
    ↓ 构建期 scripts/index.mjs
src/generated/ 课程清单 + public/ 可按需读取的正文与索引
    ↓ 浏览器请求
src/main.tsx → src/app/App.tsx → src/features/*
```

从 [React 入口](project:src/main.tsx#L1) 开始读：`createRoot` 挂载应用，`StrictMode` 帮助在开发中暴露副作用问题，`HashRouter` 让 GitHub Pages 的静态子路径可以直接刷新。

[App](project:src/app/App.tsx#App) 是应用外壳，负责课程区、主视图和源码区的组合。它不负责读取官方源码文件；这件事由 [SourceViewer](project:src/features/source/SourceViewer.tsx#SourceViewer) 完成。Markdown 的链接、术语和正文渲染集中在 [MarkdownArticle](project:src/features/learning/MarkdownArticle.tsx#MarkdownArticle)。

## 为什么要分功能目录

`src/features/learning/` 管课程阅读；`source/` 管源码浏览；`labs/` 管教学实验；`progress/` 管本地学习记录。修改一个功能时，先在对应目录找数据、视图和测试边界，不要把所有逻辑继续加进 App。

这个项目保留了一个较大的应用外壳，供你观察真实项目如何渐进拆分。企业项目继续扩展时，可把侧栏、首页、搜索弹窗等拆成独立组件，并为每个功能定义公开接口。不要为了目录层级而拆分只有两行的代码。

## 一次页面加载发生什么

1. 浏览器先获取 Vite 构建出的入口 JS、CSS 和轻量课程清单。
2. 打开某章时，阅读器按需请求 `public/教材附件/` 中对应的 Markdown。
3. 打开搜索框时，才请求全文搜索索引。
4. 打开右侧源码面板时，请求固定 React 19.3.0 或本项目构建期源码快照。

这就是 **源数据、构建产物、运行时状态** 的分界。把所有 Markdown 正文放进首页 JS 虽然能运行，却会让课程越多、首屏越重。
