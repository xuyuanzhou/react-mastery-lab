# 工程实践 04：怎样把这套结构用于企业业务应用

本项目是完整的**静态学习平台**，可以学习 React 工程组织与交付流程；它不是已经具备账号、权限、后端和业务数据库的通用企业系统。参考它时，先保留清晰边界，再按业务需要增加能力。

## 可以直接借鉴

- React + TypeScript + Vite 的入口、类型检查和构建配置。
- 按功能组织代码，避免把业务规则、网络请求和视图混在一个页面。
- 按需加载课程和源码；同样思路可用于大型报表、管理页面与富文本编辑器。
- 用 URL 表示可分享的页面状态，用本地状态表示界面交互状态。
- 用 CI 检查构建、规则和测试，发布明确的构建产物。
- 为数据加载设计加载、失败和空状态，并设置渲染错误边界。

## 需要按业务补齐

| 能力 | 本项目当前做法 | 企业业务应用通常还需要 |
| --- | --- | --- |
| 登录和权限 | 无账号 | 服务端认证、授权校验、会话过期处理 |
| 业务数据 | 静态 Markdown 和源码快照 | API 契约、缓存、重试、分页、并发冲突处理 |
| 用户数据 | `localStorage` 进度 | 服务端持久化、隐私与数据生命周期 |
| 可观测性 | 浏览器错误提示 | 脱敏日志、错误监控、性能指标 |
| 测试 | 教学算法与内容完整性 | 关键业务流程的组件、集成和端到端测试 |
| 发布 | GitHub Pages 静态部署 | 分环境配置、回滚、灰度与运营监控 |

不要仅因为「企业级」三个字就引入 Redux、微前端或复杂后端。先明确数据所有权、团队规模、性能目标和安全要求，再选择工具。
