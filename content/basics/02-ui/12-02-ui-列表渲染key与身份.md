## 核心知识

使用数组 map 将数据转换为 React 节点，用 filter 过滤数据。相邻兄弟元素需要稳定且唯一的 key，它帮助 React 在插入、删除、排序时匹配节点并保留相应组件状态。key 不传给组件作为普通 Props，若业务需要 id，应显式传入。不要在顺序会变化的列表中依赖数组下标。

## 实例：把知识应用到组件

```jsx
const tasks = [{ id: 't1', text: '读文档' }, { id: 't2', text: '写示例' }];
export default function Tasks() {
  return <ul>{tasks.map(task => (
    <li key={task.id}>{task.text}</li>
  ))}</ul>;
}
```

**阅读代码的顺序：** 先辨认组件的输入与当前状态，再找事件或外部变化的触发点，最后预测下一次渲染会产生什么界面。对于带请求、DOM 或定时器的示例，注意执行环境与清理边界。

## 常见错误与正确做法

使用 Math.random() 作为 key 会使节点每次重建；在可排序列表中使用 index 可能导致输入框的内容跟错项目。

## 自检问题

**为什么 key 不是单纯为了消除警告？**

它参与 React 的子节点匹配，决定哪些状态可以被保留和复用。
