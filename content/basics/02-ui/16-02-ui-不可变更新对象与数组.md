## 核心知识

React State 应视为只读快照。更新对象使用展开运算符创建新对象；嵌套数据需逐层复制到被修改的位置。更新数组可使用 map、filter、concat、展开语法，避免直接 push、splice、sort 原地改变状态。可读性与正确性优先，必要时再评估状态结构或辅助库。

## 实例：把知识应用到组件

```jsx
import { useState } from 'react';
export default function Todos() {
  const [todos, setTodos] = useState([{ id: 1, done: false }]);
  const toggle = id => setTodos(items => items.map(item =>
    item.id === id ? { ...item, done: !item.done } : item
  ));
  return <button onClick={() => toggle(1)}>{String(todos[0].done)}</button>;
}
```

**阅读代码的顺序：** 先辨认组件的输入与当前状态，再找事件或外部变化的触发点，最后预测下一次渲染会产生什么界面。对于带请求、DOM 或定时器的示例，注意执行环境与清理边界。

## 常见错误与正确做法

对已有 State 直接执行 todos[0].done = true；虽然数据被改了，React 仍可能无法以预期的方式更新。

## 自检问题

**为什么只复制最外层对象可能不够？**

如果继续修改被复用的嵌套对象，旧状态和新状态仍共享被改变的引用。
