## 核心知识

多个组件需要共享或协调数据时，把公共 State 放到最近的共同父组件，再通过 Props 与回调向下传递。可以由已有 State 计算出来的值不必再独立存一份，否则容易造成两份数据不一致。优先保存最少的独立状态，复杂情况再考虑 reducer 或 Context。

## 实例：把知识应用到组件

```jsx
import { useState } from 'react';
function Field({ value, onChange }) {
  return <input value={value} onChange={e => onChange(e.target.value)} />;
}
export default function Mirror() {
  const [text, setText] = useState('');
  return <><Field value={text} onChange={setText} />
    <Field value={text} onChange={setText} /><p>{text.length} 字</p></>;
}
```

**阅读代码的顺序：** 先辨认组件的输入与当前状态，再找事件或外部变化的触发点，最后预测下一次渲染会产生什么界面。对于带请求、DOM 或定时器的示例，注意执行环境与清理边界。

## 常见错误与正确做法

同时保存 text 和 textLength 并用 Effect 同步，或两个输入各存一份状态但希望它们永远一致。

## 自检问题

**什么样的数据不需要存入 State？**

每次渲染都能从 Props 或其他 State 正确计算出的数据。
