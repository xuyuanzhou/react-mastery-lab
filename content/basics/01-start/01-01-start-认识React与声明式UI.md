# 01. 认识 React 与声明式 UI

> 第一阶段 · React 入门 · 官方用法基于 React 文档；右侧源码对应本项目固定的 React v19.3.0 缓存。示例为教学代码，不是官方源码的逐行复制。

- 理解本节概念，能独立解释其使用时机与边界。
- 能运行并修改示例，说明输入变化如何影响页面。

## 核心知识

React 是负责构建用户界面的 JavaScript 库，组件根据输入的 Props 和内部 State 描述当前界面。声明式意味着写出每种状态对应的 UI，而不是逐个寻找 DOM 并修改文本。React 管理的是组件树的渲染与提交；路由、数据请求、构建工具由应用按需要组合。

## 实例：把知识应用到组件

```jsx
function Status({ online }) {
  return <p>{online ? '在线' : '离线'}</p>;
}
export default function App() {
  return <main><h1>协作空间</h1><Status online={true} /></main>;
}
```

**阅读代码的顺序：** 先辨认组件的输入与当前状态，再找事件或外部变化的触发点，最后预测下一次渲染会产生什么界面。对于带请求、DOM 或定时器的示例，注意执行环境与清理边界。

## 常见错误与正确做法

把 React 当作完整的前后端框架，或直接用 document.querySelector 修改由 React 管理的节点；这些操作会让状态和界面失去统一来源。

## 动手练习

把 Status 改造成接收用户名称与在线状态的组件，并分别渲染两种状态。

完成后，请尝试改变输入或状态，并写下你预计的输出、实际输出和差异原因。涉及浏览器的示例可以在本项目中创建练习组件运行，不要将其误认为直接复制就能独立启动的完整 Vite 工程。

## 自检问题

**为什么界面应该由数据推导？**

因为同一份数据可以在每次渲染时一致地描述 UI，无须手工维护多处 DOM 变化。
