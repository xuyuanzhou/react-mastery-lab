# 02. 数据结构：链表、环形链表、树、DFS、队列与位运算

> 学习目标：不用算法竞赛知识，也能自己画出 Hook 链、Update 环、Fiber 树；给定几个节点，能手算指针变化和 DFS 顺序。文中的小模型用于理解结构，不是 React v19.3.0 源码的逐字复制。

## 1. 先分清「节点」「指针」「遍历」

节点是保存数据的对象；指针是对象中的引用；遍历是按某种规则依次访问节点。下面 `next` 保存的是另一个对象的引用，不是字符串名字：

```js
const a = { value: 'A', next: null };
const b = { value: 'B', next: null };
a.next = b;
```

```text
变量 a ─→ [ value:A | next ] ─→ [ value:B | next:null ]
```

`a.next === b` 为 `true`。若把 `a.next = null`，B 对象不一定立即消失；只是这条连接断了。画图时先找「入口」指针，再沿箭头走。

## 2. 单向链表怎样保存 Hook 顺序

```text
Fiber.memoizedState
       │
       ▼
    Hook 1 ─next→ Hook 2 ─next→ Hook 3 ─next→ null
```

首次执行三个常规 Hook 时，React 依次把节点接在链表尾部；下次 Render 按同样的调用顺序读取对应节点。链表不知道变量叫 `count` 还是 `name`，它只知道「第一个、第二个、第三个」。

```jsx
const [count] = useState(0);  // Hook 1
const ref = useRef(null);     // Hook 2
const [name] = useState('');  // Hook 3
```

若下一次 Render 跳过 Hook 2，后面的调用会去匹配错误的位置，或触发 Hook 数量不一致错误。这是「常规 Hook 不放在条件分支」的结构原因。`use()` 有特殊调用规则，不能用这个简化模型解释全部 API。

源码实践：打开 [mountWorkInProgressHook](source:packages/react-reconciler/src/ReactFiberHooks.js#mountWorkInProgressHook)，找第一次如何设置 `memoizedState`，再看后续节点怎样经 `next` 接上。

## 3. Circular Linked List（环形链表）如何接续

普通链表最后指向 `null`；环形链表最后一个节点的 `next` 指回第一个节点。设 `pending` 只保存**尾节点 U3**：

```text
pending ─→ U3
U1.next ─→ U2
U2.next ─→ U3
U3.next ─→ U1   （环在这里闭合）

从 pending.next 出发：U1 → U2 → U3 → 回到 U1
```

因此 `pending.next` 是头节点 U1。不要误读成「pending 指向头节点」。在纸上只画一个入口箭头，再按 `next` 逐条画环，不容易画错。

### 3.1 空队列：第一次入队

```js
const u1 = { action: '+1', next: null };
u1.next = u1;  // 唯一节点指回自己
let pending = u1;
```

此时 `pending === pending.next`。单节点环不是「还没有形成环」。

### 3.2 已有 U1→U2→U3：把 U4 接到尾部

```js
const u4 = { action: '+4', next: null };
u4.next = pending.next; // 第一步：U4 → 原头 U1
pending.next = u4;        // 第二步：原尾 U3 → U4
pending = u4;             // 第三步：尾指针改指 U4
```

| 时刻 | `pending` 指向 | 环上的顺序 |
|---|---|---|
| 插入前 | U3 | U1 → U2 → U3 → U1 |
| U4 接续后 | U4 | U1 → U2 → U3 → U4 → U1 |

只改了固定数量的指针，所以**已知尾节点时，尾部插入是 O(1)**；这不表示寻找任意节点也是 O(1)。在 React 中 Update 还会带 lane，队列合并、跳过和 rebase 有更多分支；这里只学会「环怎样接续」。后续见 [useState 与 UpdateQueue](../04-useState与UpdateQueue.md) 及 [Lab 02](../labs/02-UpdateQueue与baseQueue-rebase.md)。

## 4. Tree（树）与 DFS（深度优先遍历）

树中的每个节点可以有子节点。先看一棵抽象树：

```text
A
├── B
│   ├── D
│   └── E
└── C
```

React Fiber 不在每个节点上保存 `children: [B, C]`，而常用三个方向：

- `child`：第一个子 Fiber；
- `sibling`：下一个兄弟 Fiber；
- `return`：父 Fiber（字段名叫 `return`，不是 JavaScript 的 `return` 语句）。

| Fiber | child | sibling | return |
|---|---|---|---|
| A | B | 无 | 无 |
| B | D | C | A |
| C | 无 | 无 | A |
| D | 无 | E | B |
| E | 无 | 无 | B |

画法要点：**B 的 sibling 是 C，不是 D；D 是 B 的 child。** `return` 从 B/C 指回 A，从 D/E 指回 B。

### 4.1 手算 DFS：先向下，再回头

从 A 开始，每到一个节点先处理它（对应 `beginWork` 的直觉）；有 `child` 就先走 `child`。无子节点时完成当前节点，再找 `sibling`；没有兄弟就沿 `return` 回到父节点，完成父节点后继续找父节点的兄弟。

| 步骤 | 当前动作 | 下一步依据 |
|---|---|---|
| 1 | begin A | A.child → B |
| 2 | begin B | B.child → D |
| 3 | begin D、complete D | D.sibling → E |
| 4 | begin E、complete E | E 无 sibling，return → B |
| 5 | complete B | B.sibling → C |
| 6 | begin C、complete C | C 无 sibling，return → A |
| 7 | complete A | 遍历结束 |

所以 **begin 顺序是 A、B、D、E、C；complete 顺序是 D、E、B、C、A**。DFS 不是「每一层从左到右读完」；那是广度优先遍历的直觉。

### 4.2 为什么显式指针有助于暂停

递归函数通常把「返回父节点后做什么」藏在 JavaScript 调用栈里。Fiber 用 `child/sibling/return` 和当前工作指针显式保存遍历位置，让 React 在可让出的 Render 工作中有机会停下、稍后继续或重做。**这不表示每个函数都可随时中断，也不表示 Commit 可以任意中断。**

源码实践：打开 [performUnitOfWork](source:packages/react-reconciler/src/ReactFiberWorkLoop.js#performUnitOfWork)，拿上面的五节点树找「向下」与「回头」两个方向；再读 [Fiber 结构](../01-Fiber数据结构与双缓冲.md)。

## 5. Queue（队列）与 React 的不同之处

普通 FIFO 队列像排队窗口：U1 先进入，通常先处理。React 的 UpdateQueue 仍记录更新顺序，但每条 Update 可能带不同 lane。本轮 Render 可以跳过不在所选 lanes 中的更新，并为后续重放保留基线。因此「环形链表」回答**节点怎样连接**，「lane/rebase」回答**本轮处理哪些、未来如何保序**，是两个不同问题。

## 6. Bitmask（位掩码）像集合

```js
const Sync = 0b001;       // 第 0 位
const Transition = 0b010; // 第 1 位
const selected = Sync | Transition; // 0b011，合并成员

(selected & Sync) !== 0;       // true：包含 Sync
(selected & 0b100) !== 0;      // false：不包含第 2 位
```

`|`（按位或）近似集合并集；`&`（按位与）可测试交集。`0b011` 是二进制写法，不是十进制十一。React Lane 用位集合表达可组合的更新通道；真实源码还要处理优先级、挂起、重试等，不能只把 lane 当一个数字排序。打开 [getNextLanes](source:packages/react-reconciler/src/ReactFiberLane.js#getNextLanes) 看真实分支。

## 参考答案与判分依据

1. 常规 Hook 依调用顺序匹配。少了 H2 后，后续位置不再对应原状态，可能错配或触发 Hook 数量错误；不是按变量名找 H3。
2. 头是 `pending.next`，即 U1。插入后 `pending → U4`、`U3.next → U4`、`U4.next → U1`。完整环为 U1→U2→U3→U4→U1。
3. 唯一节点指回自己，所以 `pending === pending.next`。
4. begin：A、B、D、E、C；complete：D、E、B、C、A。`B.sibling = C`，`D.return = B`。能在表格里解释每次移动，比只背两个序列更好。
5. Render 工作位置由显式 Fiber 指针保存，因而可在合适边界让出并恢复；Commit 会影响外部宿主环境，不能从 Render 的可恢复性推断它也可随意拆开。
6. OR 得到 `0b011`；AND 得到 `0b000`，所以表达式为 `false`。若只会算结果但说不清「并集/测试成员」，还需再练一次。
