# 05. 模块、打包与 React 代码为什么能在浏览器运行

> 目标：读 React 源码前先搞清楚 **ESM（ES 模块）→ Bundler（打包器）→ Bundle（浏览器产物）**。否则你会把“源码文件”“开发时模块”和“浏览器真正执行的文件”混为一谈。

## 1. 浏览器最终执行的是 JavaScript

React 项目里你常写：

```tsx
import React from 'react';
import { createRoot } from 'react-dom/client';
import App from './App';
```

这些 `import` 先构成 **Module Graph（模块依赖图）**。Vite 在开发环境利用浏览器 ESM 与开发服务器提供模块；生产构建则交给 Rollup 等工具分析依赖、拆包、压缩并输出静态资源。

## 2. JSX 不是浏览器原生 UI 指令

```tsx
root.render(<App />);
```

在送入浏览器前，JSX 会被转换成 JavaScript。现代自动 JSX Runtime 大致会生成：

```js
jsx(App, {});
```

它得到的是 **React Element（React 元素描述对象）**，还没有创建 DOM。

## 3. Tree Shaking 与 Code Splitting

- **Tree Shaking（摇树优化）**：尽量移除构建期可证明不会使用的导出。
- **Code Splitting（代码分割）**：把应用拆成多个 chunk，需要时再加载。
- **Dynamic Import（动态导入）**：`import('./Page')` 是常见代码分割边界。

这些是工程工具链行为，不等于 React Fiber 调度。

## 4. 读源码时要区分三种代码

```text
React Git 仓库源码
      ↓ 构建
发布到 npm 的包
      ↓ 应用打包
浏览器真正执行的 bundle/chunk
```

你在 `packages/react-reconciler/src/ReactFiberWorkLoop.js` 看到的是源码组织；应用线上并不会保持完全相同的文件边界。

## 自检

1. 为什么 JSX 能写在 `.tsx/.jsx` 中但浏览器并不直接理解它？
2. Module Graph 和 Fiber Tree 是同一种树吗？为什么不是？
3. Tree Shaking 是 React Runtime 的能力还是构建工具能力？

## 参考答案

1. JSX 是需要编译的语法。构建工具先把 `<App />` 转成调用 JSX Runtime 的 JavaScript，再由浏览器执行。转换结果先是 React Element 描述，不是 DOM 节点；不要把「编译 JSX」和「React Commit 创建 DOM」合成一步。
2. 不是。Module Graph 的节点是**代码模块**，边表示 import/export 依赖，在开发服务器或构建期分析；Fiber Tree 的节点是**一次 UI 的组件/宿主工作单元**，在运行时由 React 维护。一个模块可以导出多个组件，同一个组件也能在 Fiber Tree 中出现多次。
3. Tree Shaking 主要是构建工具的静态分析与输出优化。它尝试删除可证明未使用的代码；React Runtime 处理的是运行时更新和 UI。若答成「React 会根据 Fiber Tree 摇掉未使用模块」，就是把两个阶段混了。
