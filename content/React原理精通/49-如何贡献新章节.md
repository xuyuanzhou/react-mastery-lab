# 49. 怎样手写或借助 AI 增加教材章节

> 本站是静态阅读平台。网页不会直接修改仓库文件；新章节先在项目中写成 Markdown，通过检查与审阅后随下一次部署进入左侧目录、全文搜索和阅读器。完整开发者流程见仓库的 [CONTRIBUTING.md](https://github.com/xuyuanzhou/react-mastery-lab/blob/main/CONTRIBUTING.md)。

## 1. 先确定问题，再选择分组

不要为了增加篇数而重复现有章节。先用本站全文搜索检查已有解释；写出新章要解决的一句具体问题、读者需要的前置知识和一个可验证结果。分组可选学习起点、运行时、Hooks、调度、浏览器、服务端、架构、实践或附录。已有内容只需要补充时，优先改原章，而不是制造第二个互相冲突的版本。

## 2. 手写流程

在项目根目录运行：

```bash
npm run chapter:new -- --slug=your-topic --title="章节标题" --group=hooks --order=235
```

这会创建 `drafts/your-topic.md`，草稿不会上线。按模板写完整后运行：

```bash
npm run chapter:validate -- drafts/your-topic.md
```

再把文件复制到 `content/React原理精通/community/your-topic.md`，运行 `npm run check`。构建器会读取文件顶部的 `chapter-meta`，按指定分组和顺序放进课程树，并自动更新搜索索引。文件名尽量稳定；以后改标题可改一级标题，不必改路径。

## 3. 使用其他 AI 起草

可以把仓库 [AI 章节提示词](https://github.com/xuyuanzhou/react-mastery-lab/blob/main/docs/AI_CHAPTER_PROMPT.md)和[章节模板](https://github.com/xuyuanzhou/react-mastery-lab/blob/main/docs/CHAPTER_TEMPLATE.md)交给其他 AI。它能帮助组织草稿、生成图示思路和自检题，但**不能代替真实验证**。作者需要亲自核对：

1. React v19.3.0 固定 tag 中是否真有文中声称的文件、函数和分支；
2. 示例在声明的环境中是否能运行，实际结果是否与答案一致；
3. 公共 API、内部实现和本项目 Mini React 教学模型是否明确区分；
4. 图示、术语、链接、版权和引用是否准确；
5. 自检题能否只凭正文和实验完成，答案是否给出推导而非一句结论。

## 4. 审阅与发布

`npm run check` 会验证格式、源码锚点、Markdown 内链、测试和生产构建。通过后提交 PR，说明新增内容、来源和实验。人工审阅决定是否合并；合并后 GitHub Pages 自动发布。读者的本地“已读/书签”存于浏览器，新增章节上线不会替他自动标记已学。

## 自检

1. AI 生成了 `source:...#someFunction`，但校验失败，应如何处理？
2. 为什么不能在网页里直接上传一个 Markdown 就立即公开？

## 参考答案

1. 回到固定 v19.3.0 源码核对真实文件与 symbol；若不存在，纠正事实或删除该链接，不能为通过构建虚构一个函数。
2. 本站是静态部署，没有写入仓库的服务端和审阅权限流程。直接公开会绕过版本、链接、实验和版权核查；应走本地草稿、验证、PR 审阅和自动部署。
