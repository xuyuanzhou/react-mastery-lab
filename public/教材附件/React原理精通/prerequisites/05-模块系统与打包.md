# 08. 模块、打包与 React 代码为什么能在浏览器运行

> 目标：读 React 源码前先搞清楚 **ESM（ES 模块）→ Bundler（打包器）→ Bundle（浏览器产物）**。否则你会把“源码文件”“开发时模块”和“浏览器真正执行的文件”混为一谈。

## 1. 浏览器最终执行的是 JavaScript

React 项目里你常写：

```tsx
import React from 'react';
import { createRoot } from 'react-dom/client';
import App from './App';
```

这些 `import` 先构成 **Module Graph（模块依赖图）**。Vite 在开发环境利用浏览器 ESM 与开发服务器提供模块；生产构建则交给 Rollup 等工具分析依赖、拆包、压缩并输出静态资源。

## 2. JSX 不是浏览器原生 UI 指令

```tsx
root.render(<App />);
```

在送入浏览器前，JSX 会被转换成 JavaScript。现代自动 JSX Runtime 大致会生成：

```js
jsx(App, {});
```

它得到的是 **React Element（React 元素描述对象）**，还没有创建 DOM。

## 3. Tree Shaking 与 Code Splitting

- **Tree Shaking（摇树优化）**：尽量移除构建期可证明不会使用的导出。
- **Code Splitting（代码分割）**：把应用拆成多个 chunk，需要时再加载。
- **Dynamic Import（动态导入）**：`import('./Page')` 是常见代码分割边界。

这些是工程工具链行为，不等于 React Fiber 调度。

## 4. 读源码时要区分三种代码

```text
React Git 仓库源码
      ↓ 构建
发布到 npm 的包
      ↓ 应用打包
浏览器真正执行的 bundle/chunk
```

你在 `packages/react-reconciler/src/ReactFiberWorkLoop.js` 看到的是源码组织；应用线上并不会保持完全相同的文件边界。
