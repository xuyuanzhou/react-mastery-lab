# 02. 数据结构：链表、树、队列与位运算

> 目标：只补 React 源码真正高频使用的数据结构，不要求算法竞赛水平。你需要能“看懂结构为什么这样组织”。

## 1. Linked List（链表）

链表节点用指针连接下一个节点：

```js
const a = { value: 'A', next: null };
const b = { value: 'B', next: null };
a.next = b;
```

React Hooks 的关键心智模型就是链表：

```text
Fiber.memoizedState
      ↓
    Hook 1
      ↓ next
    Hook 2
      ↓ next
    Hook 3
```

因此 Hook 的“身份”与调用顺序强相关。更新时如果少调用一个常规 Hook，后续节点就会错位。

源码入口：[mountWorkInProgressHook](source:packages/react-reconciler/src/ReactFiberHooks.js#mountWorkInProgressHook)。

## 2. Circular Linked List（环形链表）

UpdateQueue 的 `pending` 常以环形结构表达：只保存尾节点，也能通过 `pending.next` 找到头节点。

```text
pending → U3
          ↓
U1 ← U2 ←┘
↑       ↓
└───────┘
```

这让尾部插入保持 O(1)。

## 3. Tree（树）与 DFS（深度优先遍历）

Fiber 不是典型的 `children[]` 树，而用：

```text
child   → 第一个子节点
sibling → 下一个兄弟节点
return  → 父节点
```

所以 React 可以自己控制 DFS，而不是完全依赖 JavaScript 递归调用栈。

## 4. Queue（队列）

普通队列强调“先进入、先处理”。React UpdateQueue 更复杂：更新还带 Lane，不同 render 可能跳过某些 Update，之后还要 rebase，因此不能把它理解成一个简单 FIFO 数组。

## 5. Bitmask（位掩码）

每一位都可以表示一个集合成员：

```js
const Sync = 0b001;
const Transition = 0b010;
const selected = Sync | Transition;
console.log((selected & Sync) !== 0); // true
```

React Lane 使用位集合表示可组合的更新通道。源码入口：[getNextLanes](source:packages/react-reconciler/src/ReactFiberLane.js#getNextLanes)。
