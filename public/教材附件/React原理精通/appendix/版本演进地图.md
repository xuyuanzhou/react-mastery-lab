# React 版本演进地图：从约束变化理解架构

## React 15：Stack Reconciler

```text
Class instance
+ synchronous recursive reconciliation
+ lifecycle methods
```

主要限制：长递归工作不易分片/暂停；更新模型与 JS call stack 强绑定。

## React 16：Fiber

关键变化不是“新的 Virtual DOM”，而是把工作显式化：

```text
Fiber node
+ child/sibling/return
+ current/WIP
+ flags
```

这为可中断 Render、错误边界等提供架构基础。

## React 16.8：Hooks

Function Component 获得 state/effect 能力。核心转变：

```text
Class: state on instance
Function: persistent state on Fiber/Hook structures
```

## React 17：升级桥梁与事件系统变化

更关注渐进升级和事件委托位置调整，而非新增大量用户 API。

## React 18：Concurrent architecture 面向用户开放

`createRoot`、automatic batching、transition、Suspense 等让优先级和可中断渲染成为主流运行模型。

## React 19 / 19.1

Actions、`use`、`useOptimistic`、`useActionState`、ref 相关改进以及 Server Components 生态继续成熟。

## React 19.2

Activity、`useEffectEvent`、cacheSignal、性能轨道与服务端/预渲染能力继续增强。

## React 19.3

ViewTransition、Fragment Refs、browser API、Trusted Types 等进入稳定版本；Transitions 的调度语义也继续演进。

## 读版本历史的正确方式

不要背“某版本新增 API 清单”。每次问：

```text
旧架构的哪一个约束暴露了？
→ React 新增了哪一层状态/协议？
→ 用户 API 如何把这层能力暴露出来？
→ 为了兼容旧语义付出了什么复杂度？
```
