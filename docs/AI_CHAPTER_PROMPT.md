# 给其他 AI 的章节写作提示词

将下面内容连同需要扩展的主题发给 AI。AI 产出只能作为草稿，仍须由人核对 React 官方文档、固定版本源码、实验结果与版权。

```text
请为 React Mastery Lab 写一篇中文 Markdown 教学章节，读者会写基本 React 组件，但不预设懂 Fiber、调度或数据结构。

版本语境：公共 API 以 React 官方文档为准；内部机制必须以 facebook/react 的 v19.3.0 tag 核对。区分稳定 API、版本特定内部实现和教学简化模型，不要把三者混写。

请遵守 docs/CHAPTER_TEMPLATE.md 的标题顺序。正文必须：
1. 从一个可观察的 UI 问题出发，先让读者预测，再解释因果。
2. 用具体数据结构、步骤和图表解释内部机制；图中每条箭头都要解释。
3. 至少给一个真实的 source:packages/...#symbol 锚点，且只能写已在 v19.3.0 源码中核对存在的文件和函数。不要猜行号或函数名。
4. 给最小可运行实验、预期结果、反例、版本/环境边界。
5. 给至少两道能手算或预测的自检题，并在同篇给逐步参考答案；答案不能只重复题目或一句结论。
6. 给对应 React 官方文档链接；来源之外的推论明确写成推论。
7. 不复制官方源码或第三方文章的大段文字，只引用短片段并说明原理。
8. 避免“总是”“必然”之类绝对时序断言；确需断言时写前提和可验证条件。

只输出 Markdown 草稿，不要声称它已被验证、已发布或能保证读者精通。完成后列出你无法核实的源码锚点与实验观察，供人类复核。
```

审核者把草稿保存到 `drafts/`，补齐事实后运行 `npm run chapter:validate -- drafts/<slug>.md`。通过后复制到 `content/React原理精通/community/`，运行 `npm run check`，最后提交 PR。
